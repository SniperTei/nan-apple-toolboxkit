# 崩溃日志集成说明

## 概述

我们已经成功将崩溃监控功能与现有的日志模块集成，实现了崩溃信息的统一记录和管理。

## 主要修改

### 1. 日志类型扩展

在 `SNPLogConst.swift` 中添加了新的日志类型：

```swift
public enum SNPLogInfoType {
    case info
    case network
    case error
    case warning
    case crash  // 新增崩溃日志类型
}
```

### 2. 日志管理器增强

在 `SNPLogManager.swift` 中：

- 添加了崩溃日志的便捷方法：`SNPLogManager.crash(_:)`
- 扩展了日志指示器，支持 `CRASH` 标识

### 3. 崩溃监控器集成

在 `SNPCrashMonitor.swift` 中：

- 监控启动/停止时记录日志
- 异常崩溃时使用 `.crash` 类型记录详细信息
- 信号崩溃时使用 `.crash` 类型记录详细信息
- 包含异常名称、原因、调用栈等完整信息

### 4. 测试控制器增强

在 `SNPCrashTestController.swift` 中：

- 日志方法同时写入日志模块和UI显示
- 崩溃回调中使用 `.crash` 类型记录完整崩溃信息
- 添加了崩溃日志测试功能

## 日志格式

崩溃日志采用以下格式：

```
[时间戳] [CRASH] [文件名:行号] 函数名 - 崩溃详细信息
```

崩溃详细信息包括：
- 崩溃类型（异常/信号）
- 异常名称和原因
- 信号类型和描述
- 完整调用栈
- 设备信息
- 时间戳

## 使用示例

### 记录崩溃信息

```swift
// 在崩溃监控器中
SNPLogManager.shared.writeLog(
    log: crashInfo,
    type: .crash,
    file: #file,
    function: #function,
    line: #line
)

// 使用便捷方法
SNPLogManager.crash("崩溃信息")
```

### 测试崩溃日志

在崩溃测试控制器中点击"测试崩溃日志记录"按钮，可以测试崩溃日志的记录功能。

## 优势

1. **统一管理**：所有日志（包括崩溃信息）都在同一个日志系统中管理
2. **分类清晰**：使用专门的 `.crash` 类型区分崩溃日志
3. **信息完整**：记录崩溃的详细信息，便于问题定位
4. **易于查询**：可以通过日志类型快速筛选崩溃信息
5. **双重记录**：既记录到文件，也在UI中显示

## 注意事项

1. 崩溃日志使用 `.crash` 类型，便于后续分析和筛选
2. 崩溃信息包含敏感数据（调用栈等），注意日志文件的安全
3. 建议定期清理旧的崩溃日志文件
4. 在生产环境中可以配置崩溃日志的上传功能
